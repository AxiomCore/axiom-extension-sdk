# Axiom TypeScript extension SDK

This package is an npm dependency owned and pinned by Axiom. It exposes no
network, filesystem, process, environment, timer, random, dynamic-loading, or
native-addon API. The generated runner communicates only through bounded
stdin/stdout supplied by the trusted TypeScript kernel and returns the same
typed ABI results consumed by the capability broker.

Application extensions install `@axiomcore/extension-sdk` in their project,
import `defineExtension` from it, and import generated selectors from
`@axiomcore/extension-bindings`. The latter module is generated by the Axiom
CLI for each extension interface.

The working 0.1.2 candidate adds selected finite input/output types and named
continuations. `defineSelectedExtension` comes from the generated bindings.
An export uses `context.complete(value)` or
`context.effects.<continuation>(state, inputs)`; its named `resume` handler
consumes typed branch outcomes. The host performs authorized effects and invokes
a fresh continuation with checked state and replies. Guest heap state is not a
continuation contract.

Selected pure packages use package schema v2 and named-continuation packages use
v3, while the wire ABI remains v1. The initial managed source profile rejects
handles, arbitrary Promise/async work, streams in named continuations and ambient
I/O. Interface generation never adds grants or raises host budgets.

The complete source example is
`examples/advanced-language-dx/selected-extensions/typescript` in the AxiomCore
workspace. Use the exact SDK, generated selection and managed toolchain from
that cohort. These working candidate capabilities do not establish registry
publication or browser/mobile qualification.

## Typed tickets

```ts
import { defineExtension, operation, type Effects } from "@axiomcore/extension-sdk";

const name = operation<{ id: number }, string>("catalog", "name");
const stock = operation<number, boolean>("catalog", "stock");
// One function builds the plan, for the export and for the resume.
const lookup = (plan: Effects, id: number) => ({
  name: plan.push(name.call({ id })),
  stock: plan.push(stock.call(id)),
});

export default defineExtension({
  exports: { run: (ctx) => { const plan = ctx.plan(); lookup(plan, 7); return ctx.effects(plan); } },
  resume: (resume) => {
    const t = lookup(resume.plan(), 7);   // same calls, same inputs, same order
    return resume.complete({ name: resume.get(t.name), stock: resume.get(t.stock) });
  },
});
```

`resume.get(t.name)` is typed `string`; a forged ticket does not type-check and
is rejected at runtime. `resume.outcome(i)` is deprecated, and so is
`Effects.call` (use `push`). A later yield step from a resume uses
`yieldFor(plan)`.

In TypeScript and Python every exchange runs in a fresh engine, so tickets
do not survive from the export to the resume. The resume rebuilds the plan it
answers with `resume.plan()`: the **same calls (namespace, operation and
input) in the same order**, usually by calling the same function that built
the yielded plan. The managed host echoes its record of the yielded plan with
the resume, and `get` rejects a rebuilt plan that differs, naming the first
differing call (for example `call 0 is catalog.stock, the yielded call 0 was
catalog.name`). Inputs are compared exactly up to 8 KiB per call and 64 KiB
per plan; larger inputs are compared by their canonical length. A plan of more
than about 1,700 calls, or a host that predates the echo, gets only the
call-count check. When a resume cannot rebuild its plan deterministically, use
a named continuation, whose state the host carries.

## Portable schema source checks

The portable validation helper has a checked source binding in
`schema-runtime.source.json`. Standalone SDK validation verifies both the
generated helper and its source hash; workspace validation also compares the
actual host helper when that checkout is present. CI does not need access to a
private sibling repository.

Maintainers synchronize a reviewed helper from the workspace with
`python3 -B scripts/sync_portable_schema.py --host-source ../axiom-ui-host/web/acore-schema.js`
at the SDK repository root. Add `--check` to reject drift without writing files.
